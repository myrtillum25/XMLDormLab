## Тематика: «Гуртожиток»

База даних мешканців студентського гуртожитку (`Dormitory.xml`):
- Дворівнева структура: кореневий вузол `<Dormitory>` та дочірні елементи `<Student>`.
- Різна кількість атрибутів у різних вузлів (наявність пільг `benefit`, контактного телефону `phone`, статусу старости кімнати `isRoomHead`).

### Атрибути вузла `<Student>`:
- `fullName` — П.І.Б. студента;
- `faculty` — факультет (ФКНК, Мехмат, ФРЕКС тощо);
- `department` — кафедра / спеціальність;
- `roomNumber` — номер кімнати в гуртожитку;
- `course` — курс навчання;
- `checkInDate` — дата поселення;
- `benefit` — пільга (за наявності);
- `isRoomHead` — чи є старостою кімнати (`true` / `false`);
- `phone` — контактний номер телефону.

## Патерн проєктування «Стратегія» (Strategy)

Для аналізу та фільтрації вмісту XML реалізовано 3 взаємозамінні алгоритми (патерн **Strategy**):

| Стратегія | Клас | Опис та технологія |
|---|---|---|
| **DOM API** | `DomSearchStrategy` | Завантажує весь XML-документ у пам'ять у вигляді об'єктного дерева (`XmlDocument`), вибірка вузлів через XPath. |
| **SAX API** | `SaxSearchStrategy` | Швидке потокове односпрямоване читання файлу без завантаження всього документа в пам'ять (`XmlReader`). |
| **LINQ to XML** | `LinqToXmlSearchStrategy` | Сучасна декларативна фільтрація через `XDocument` та LINQ-запити. |

Клас `XmlSearchContext` інкапсулює посилання на поточну стратегію та дозволяє перемикати її під час роботи програми через перемикачі.

## Можливості та функції програми

- **Вибір та завантаження XML-файлу:** користувач може вказати будь-який XML-документ через системний діалог.
- **Динамічна «підгрузка даних»:** після завантаження XML програма аналізує всі наявні вузли та автоматично заповнює випадаючі списки (`Picker`) унікальними значеннями факультетів та кімнат, які реально присутні у файлі.
- **Гнучка фільтрація:** пошук за факультетом, номером кімнати, курсом, а також швидкий пошук за підрядком у П.І.Б. чи іншими ключовими словами.
- **Очищення форми (кнопка Clear):** миттєве скидання всіх обраних фільтрів і списку результатів.
- **XSLT-трансформація у HTML:** перетворення XML-файлу на HTML-звіт за допомогою таблиці стилів `Transform.xsl` з можливістю відкриття у веб-браузері.
- **Підтвердження виходу:** діалогове вікно попередження перед закриттям програми (*«Чи дійсно ви хочете завершити роботу?»*).
- **Відсутність антишаблону «Магічна кнопка» (Magic Pushbutton):** уся логіка пошуку та обробки винесена в окремі класи сервісів, обробники кнопок у `MainPage.xaml.cs` лише делегують виклики.

## Структура проєкту

```
XMLDormLab/
├── Dormitory.xml           — вихідна база даних мешканців гуртожитку
├── Transform.xsl          — XSLT-шаблон для стилізації та генерації HTML-звіту
└── DormitoryApp/
    ├── Models/
    │   ├── Student.cs      — модель студента гуртожитку
    │   └── SearchFilter.cs — параметри пошуку та фільтрації
    ├── Services/
    │   ├── IXmlSearchStrategy.cs     — інтерфейс патерна Strategy
    │   ├── DomSearchStrategy.cs      — реалізація через DOM (XmlDocument)
    │   ├── SaxSearchStrategy.cs      — реалізація через SAX (XmlReader)
    │   ├── LinqToXmlSearchStrategy.cs — реалізація через LINQ to XML
    │   ├── XmlSearchContext.cs       — контекст патерна Стратегія
    │   └── XsltTransformer.cs        — сервіс XSLT-трансформації в HTML
    ├── MainPage.xaml       — графічний інтерфейс користувача (.NET MAUI)
    ├── MainPage.xaml.cs    — логіка взаємодії UI з сервісами
    └── App.xaml / MauiProgram.cs
```
